# Glossary

| Term | Meaning |
|---|---|
| API | Contract that lets software systems communicate |
| CRUD | Create, Read, Update, Delete |
| JVM | Runs Java bytecode |
| JRE | JVM plus runtime libraries |
| JDK | JRE plus development tools |
| OOP | Programming organized around objects |
| Class | Blueprint for objects |
| Object | Instance of a class |
| Encapsulation | Controlled access to data and behavior |
| Abstraction | Hiding unnecessary implementation detail |
| Inheritance | Reusing parent-class behavior |
| Polymorphism | Same interface, different behavior |
| MVC | Model, View, Controller architecture |
| ORM | Maps application objects to database records |
| SQL | Language for relational databases |
| NoSQL | Non-relational database category |
| JSON | Common API data-exchange format |
| REST | Resource-oriented API design style |
| Middleware | Code that runs during request processing |
| Component | Reusable UI building block |
| Props | React inputs passed by a parent |
| State | Changeable component data |
| Index | Structure that can speed database lookup |
| Transaction | Group of database operations treated as one unit |
| ACID | Atomicity, Consistency, Isolation, Durability |
| Git | Distributed version-control system |
| Commit | Saved Git snapshot |
| Branch | Independent development line |
| Deployment | Making software available in an environment |
| Horizontal scaling | Adding more instances |
| Authentication | Confirming identity |
| Authorization | Checking permissions |
