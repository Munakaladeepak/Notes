# Figma and UI/UX

**Priority:** Low · **Prerequisite:** [[07 - Web Technologies/README|Web Technologies]]

## Design handoff

Figma provides wireframes, high-fidelity screens, prototypes, components, variants, design tokens, and developer handoff. Extract intent, not just pixels: identify reusable components, spacing scale, typography, colors, assets, breakpoints, and interaction states.

## UI systems

A design system standardizes components and tokens. Auto layout communicates flexible sizing and spacing. Variants represent states or options. Consistency reduces implementation ambiguity and improves accessibility.

## States and UX

Every CRM screen should consider loading, empty, success, validation error, server error, disabled, hover, focus, and permission-denied states. Tables need pagination or virtualization for large data. Destructive actions should communicate consequences and require an appropriate confirmation pattern.

## Accessibility

Use semantic HTML, keyboard navigation, visible focus, labels, error associations, readable contrast, and non-color-only meaning. Responsive behavior must preserve task completion, not only visual similarity.
