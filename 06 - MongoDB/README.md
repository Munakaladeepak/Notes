# MongoDB

**Priority:** High · **Prerequisite:** [[05 - MySQL and SQL/README|MySQL and SQL]] · **Related:** [[09 - Node and Express/README|Node and Express]]

## Document model

MongoDB is a document-oriented NoSQL database. A database contains collections, and collections contain BSON documents. BSON extends JSON with additional types. `_id` uniquely identifies a document by default when generated by MongoDB.

## CRUD and query thinking

Know `insertOne`, `insertMany`, `find`, `findOne`, `updateOne`, `updateMany`, `deleteOne`, and `deleteMany`. Updates may use operators such as `$set`, `$inc`, `$push`, `$addToSet`, `$pull`, and `$unset`. Query operators include `$gt`, `$gte`, `$lt`, `$in`, `$exists`, `$or`, and `$and`.

## Modeling

Embedding stores related data in a parent document and can make one-read workflows efficient. Referencing stores an identifier and requires additional retrieval logic. Decide using cardinality, growth, update frequency, ownership, and read patterns. Avoid unbounded arrays inside documents.

## Aggregation

An aggregation pipeline passes documents through stages. Common stages are `$match`, `$project`, `$group`, `$sort`, `$limit`, `$unwind`, and `$lookup`. Place selective `$match` stages early where appropriate. Grouping and lookup can be expensive, so model around real access patterns.

## Indexes and consistency

Indexes improve supported reads but consume memory/storage and increase write cost. Compound index field order matters. MongoDB supports atomic document operations and multi-document transactions, but transaction use does not remove the need for good schema design.

## Relational comparison

MySQL starts with normalized tables and relationships; MongoDB starts with documents shaped around access patterns. MongoDB is not “better because it is NoSQL.” Choose based on joins, schema variability, consistency, scale, and query patterns.
